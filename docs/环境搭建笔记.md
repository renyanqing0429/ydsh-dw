# 环境搭建笔记

> 记录 Docker / Hive / MySQL 环境搭建过程中遇到的问题与解决方案（子任务 2 交付物）。

## 一、环境信息

| 组件 | 版本 | 说明 |
|---|---|---|
| 操作系统 | Windows | 需 WSL2 后端 |
| Docker Desktop | 待安装 | 官网下载，勾选 WSL 2 backend |
| Hive | 4.0.0（apache/hive 镜像） | 含 Metastore 与 HiveServer2 |
| MySQL | 8.0 | 作 Metastore 元数据库 |

## 二、搭建步骤（对应操作手册）

1. 安装 Docker Desktop（勾选 WSL 2 backend），安装后重启电脑
2. 验证：`docker --version`、`docker compose version`
3. 项目根目录执行 `docker compose up -d` 拉起 mysql / hive-metastore / hive-server
4. `docker ps` 确认三个容器 Up
5. 连接验证：`docker exec -it hive-server beeline -u jdbc:hive2://localhost:10000`
6. 执行 `show databases;`、`create database if not exists ydsh_ods;`

## 三、遇到的问题与解决方案

### 问题 1：Edge 下载 Docker Desktop 安装包失败（ERR_CONNECTION_RESET）
- 现象：浏览器访问 `desktop.docker.com` 下载页显示"无法访问此页面"，右上角防火墙显示"公用网络（使用中）"
- 排查：命令行 `curl -I` 访问同一 URL 返回 `HTTP/1.1 200 OK`，`Content-Length: 641758128`
- 原因：浏览器层面的网络/代理问题，非目标站点不可达
- 解决：改用命令行下载（支持断点续传，不受浏览器代理设置影响）

```bash
curl -L --retry 3 -C - -o "$HOME/Downloads/DockerDesktopInstaller.exe" \
  "https://desktop.docker.com/win/main/amd64/Docker%20Desktop%20Installer.exe"
```

### 问题 2：静默安装 Docker Desktop
- 命令：`DockerDesktopInstaller.exe install --quiet --accept-license --backend=wsl-2`
- 要点：需管理员权限（会弹 UAC），安装耗时约 2 分钟，返回码 0 表示成功
- 安装后版本：Docker 29.9.2 / Docker Compose v5.6.1

### 问题 3：引擎起不来，日志报 `Access is denied`（写 ~/.docker/config.json 失败、调 wsl.exe 失败）
- 现象：`docker ps` 报 `open //./pipe/docker_engine: The system cannot find the file specified`
- 日志：`C:\Users\<用户>\AppData\Local\Docker\log\host\com.docker.backend.exe.log` 中
  - `rename <HOME>\.docker\daemon.json: Access is denied`
  - `c:\windows\system32\wsl.exe --version failed: fork/exec ...: Access is denied`
- 原因：Docker Desktop 由受限制的进程启动，继承了进程策略限制，导致无法写用户目录、无法调用 wsl.exe
- 解决：**从开始菜单（或桌面快捷方式）手动启动 Docker Desktop**，让它作为独立进程运行；确认系统托盘鲸鱼图标变为绿色

### 问题 4：WSL2 未安装导致引擎无法启动
- 前置检查：`VirtualizationFirmwareEnabled: True`（BIOS 已开启虚拟化），但 `HypervisorPresent: False`、无已安装发行版
- 处理：Docker Desktop 首次启动会提示安装/enable WSL2（需管理员 + 重启一次）

### 问题 5：HiveServer2 起不来（Metastore 未就绪）
- 原因：Hive 依赖 HDFS + Metastore（MySQL），启动有顺序依赖
- 解决：compose 中已配置 `depends_on: condition: service_healthy`，mysql 健康检查通过后再启 metastore

### 问题 6：10000 端口被占用
- 排查：`netstat -ano | findstr 10000`
- 解决：结束占用进程，或修改 compose 端口映射

### 问题 7：CSV 导入行数与预期不符
- 原因：表头被当成数据 / 分隔符不匹配
- 解决：建表加 `tblproperties('skip.header.line.count'='1')`，确认 `FIELDS TERMINATED BY ','`


### 问题 8：docker pull 拉取镜像超时（registry-1.docker.io 连接失败）
- 现象：`docker compose up` 报 `Get "https://registry-1.docker.io/v2/": context deadline exceeded`
- 解决：改用国内镜像源"前缀拉取 + 重新打 tag"，无需改 daemon 配置、无需重启 Docker

```bash
docker pull docker.m.daocloud.io/library/mysql:8.0
docker tag  docker.m.daocloud.io/library/mysql:8.0 mysql:8.0
docker pull docker.m.daocloud.io/apache/hive:4.0.0
docker tag  docker.m.daocloud.io/apache/hive:4.0.0 apache/hive:4.0.0
```

- 备选可用源（`curl -s https://<源>/v2/` 返回 401/200 即存活）：docker.1ms.run、docker.1panel.live、docker.xuanyuan.me

### 问题 9：宿主机 3306 端口被占用
- 现象：`ports are not available: ... bind: Only one usage of each socket address`
- 原因：本机已装并运行了 MySQL 服务
- 解决：compose 中宿主机端口改为 `"3307:3306"`；Metastore 走容器内部网络（mysql:3306）不受影响

### 问题 10：Metastore 启动失败：ClassNotFoundException: com.mysql.cj.jdbc.Driver
- 原因：apache/hive:4.0.0 官方镜像不含 MySQL JDBC 驱动，schemaTool 初始化 metastore_db 失败退出
- 解决：下载 mysql-connector-java-8.0.30.jar（阿里云 Maven 镜像），在 compose 中挂载进容器类路径：

```yaml
volumes:
  - ./jars/mysql-connector-j.jar:/opt/hive/lib/mysql-connector-j.jar:ro
```

### 问题 11：Windows Git Bash 下 docker exec 路径被改写
- 现象：`beeline -f /sql/ods/create_ods.sql` 报 `No FileSystem for scheme "C"`
- 原因：MSYS 终端会把 `/sql/...` 自动转换成 Windows 路径再传给 docker
- 解决：`export MSYS_NO_PATHCONV=1`，或改用 `docker cp` 把脚本拷进容器后在容器内执行

### 问题 12：管道方式执行 SQL 中文注释变问号
- 现象：`< script.sql | docker exec -i ... beeline` 建表后注释显示 `????`
- 原因：Windows 管道默认编码与容器 JVM 字符集不一致
- 解决：`docker cp` 拷贝脚本文件到容器内执行（文件直读不经管道）；中文注释存库仍受 JDBC 连接字符集影响显示为 ?，不影响数据与查询结果

### 问题 13：Docker 引擎重启后三容器全部 Exited (255)
- 原因：宿主机重启/引擎重启会杀掉旧容器；Docker Desktop 设置里未开启容器自动恢复
- 解决：`docker compose up -d` 重新拉起即可（数据卷 mysql_data 保留，元数据不丢）

### 问题 14：hive-server 重启报 "HiveServer2 running as process 7. Stop it first."
- 原因：`docker compose restart` 保留容器文件系统，/tmp 下的陈旧 PID 文件让启动脚本误判已在运行
- 解决：**`docker compose down`（删除容器）+ `up -d` 重建**，不要用 restart；或启动命令前加 `rm -f /tmp/*.pid`

## 七、第 2 周新增问题记录（2026-11-02）

### 问题 15：hive-server 启动即退出，日志报 "HiveServer2 running as process 7. Stop it first."

**现象**：`docker compose up -d` 后 hive-server 状态为 `Exited (1)`，日志出现
`HiveServer2 running as process 7. Stop it first.` + 进程列表。

**原因**：官方 `apache/hive:4.0.0` 镜像的 entrypoint 在容器内被重复触发（容器首次启动初始化 schema 与启动服务的竞态），
第二次启动检测到已有 hiveserver2 进程便主动退出。

**解决**：强制重建该容器即可，无需改动配置：

```bash
docker compose up -d --force-recreate hive-server
sleep 20
docker logs --tail 20 hive-server     # 出现 "Starting HiveServer2" 即正常
```

**经验**：`run_pipeline.sh` 里已有最长 5 分钟轮询等待逻辑；若等待超时，先看 `docker ps -a` 是否 Exited，
是则 `--force-recreate` 后重跑，不要反复 `down/up` 整个 compose。

### 问题 16：容器重建后表还在，但查询报 "Input path does not exist"

**现象**：`SHOW TABLES` 能列出表，`SELECT COUNT(*)` 报
`java.io.IOException: Input path does not exist: file:/opt/hive/data/warehouse/ydsh_ods.db/ods_user`。

**原因**：Metastore 元数据存在 MySQL（name volume 持久化），但表数据在本容器本地文件系统（未挂卷），
容器重建后数据文件丢失，元数据与数据不一致。

**解决**：重跑全量流水线（`bash tools/run_pipeline.sh all`），脚本会先删库再重建并重新导入。
长期方案：把 `/opt/hive/data/warehouse` 挂到 named volume。

### 问题 17：动态分区写入失败 "The maximum number of dynamic partitions ... 100 partitions per node"

**现象**：按天分区（366 个分区）写入 `dwd_order` 时报
`Fatal error occurred when node tried to create too many dynamic partitions ... Maximum was set to 100 partitions per node`。

**解决**：在加载脚本开头放开上限（2000 足够覆盖全年 366 天）：

```sql
SET hive.exec.dynamic.partition = true;
SET hive.exec.dynamic.partition.mode = nonstrict;
SET hive.exec.max.dynamic.partitions = 2000;
SET hive.exec.max.dynamic.partitions.pernode = 2000;
```

### 问题 18：Counters limit exceeded: Too many counters: 121 max=120

**现象**：一条 SQL 里包含十几个 `UNION ALL` 分支或多个标量子查询时，报
`Counters limit exceeded: Too many counters: 121 max=120`，执行失败。

**原因**：Tez 每个算子都会注册计数器，分支过多会超过 Hadoop 的
`mapreduce.job.counters.limit`（默认 120）。会话内 `SET` 该参数在本环境无效。

**解决**：拆分 SQL —— 按脏数据类别分成多条 `INSERT`，或把多标量子查询改写成 `UNION ALL` 单表计数；
单条语句的分支数控制在 4 个以内。

### 问题 19（重要）：Hive 4 的 CREATE TABLE 默认是外部表，DROP 后重建会导致数据翻倍

**现象**：脚本里写了 `DROP TABLE IF EXISTS t; CREATE TABLE t (...); INSERT INTO TABLE t VALUES ...`，
第二次执行脚本后 `COUNT(*)` 翻倍（如编码映射表 11 行 → 22 行），并进一步让 JOIN 结果成倍膨胀
（`stg_order_merge` 一度从 15,000 变成 120,000）。

**原因**：Hive 4.0 的 `CREATE TABLE` 默认创建 **EXTERNAL_TABLE**（`DESCRIBE FORMATTED` 可见
`Table Type: EXTERNAL_TABLE`）。外部表 `DROP TABLE` 只删除元数据、不删除数据文件；
重新 `CREATE TABLE` 会重新挂载同一目录的旧文件，随后 `INSERT INTO` 追加，于是行数翻倍。

**解决（三选一，本项目全部采用）**：

1. 一次性写入的映射表：用 `INSERT OVERWRITE TABLE ... VALUES` 代替 `INSERT INTO TABLE`；
2. 事实/维度表加载：统一使用 `INSERT OVERWRITE TABLE`（会清空目录再写入，天然幂等）；
3. 需要多次追加的中间表（如质量统计表）：每类的第一条用 `INSERT OVERWRITE`，其余用 `INSERT INTO`；
4. 流水线重置数据库时同步清理目录（`run_pipeline.sh` 已加）：
   `docker exec hive-server bash -c 'rm -rf /opt/hive/data/warehouse/ydsh_ods.db'`。

**经验**：写 Hive 脚本时默认外部表假设，所有写入都按「可重复执行」设计，避免脚本跑两遍结果就不对。
