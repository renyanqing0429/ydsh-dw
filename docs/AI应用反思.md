# AI 应用反思

**课程**：企业项目实战实训 · 第 3 周　**团队**：云购数仓组　**作者**：任宴庆

本周在项目中落地了三类 AI 能力：**NL2SQL 自然语言查数**（`src/nl2sql/`）、**大模型异常归因与自动报告**（`src/insight/`）、**最小化 API 调用与密钥管理**（`src/llm/`）。本反思按照任务书要求，从能力、偏见与局限、验证方法三个层面审视本周的 AI 应用。

---

## 一、AI 在本项目中的实际价值

1. **降低数据使用门槛**。NL2SQL 把"会写 SQL"这个硬门槛变成"会提问题"，让不懂 SQL 的业务同学也能直接查数（"广东省上月销售额"→ 一条带 JOIN 的 Hive SQL，实测返回 45,904.87 元）。这是数据仓库"最后一公里"的真实痛点。
2. **提升分析初稿效率**。异常归因、经营摘要这类"初稿型"工作交给大模型，分析师把精力转向验证与决策，形成"AI 起草、人审核"的协作模式。
3. **倒逼口径显性化**。要让大模型生成正确的 SQL，必须先把 Schema、GMV 口径（`pay_amount_valid`）、时间粒度白纸黑字写进 Prompt——**AI 应用反过来推动了团队的数据治理**，这是本周最有价值的意外收获。

## 二、AI 可能存在的偏见与局限（结合实测）

### 2.1 数据边界内的"一本正经胡说"（幻觉风险）

- 大模型可能编造不存在的表名/字段名（如 `user_info`）。**实测对策**：我们的安全校验器会对 Schema 白名单之外的表名直接拒绝执行（`executor.validate_sql`），实测已拦截。
- 归因结论可能给出看似合理的因果解释。但本数据集**没有**促销日历、天气、竞品、投放数据——模型给出的"原因"只能是假设，无法定证。AI 不知道自己不知道什么，这必须由人来兜底。

### 2.2 训练数据偏见传导

- 大模型见过的零售案例多来自电商大促场景，容易先入为主把波动归因为"促销节奏"，而我们的模拟数据根本没有促销——**先验会污染归因**。Prompt 中已显式声明"本平台无促销数据"以抑制这种倾向。
- 若上游数据本身有偏差（如模拟数据 1000 用户人均 10 单、复购率饱和 100%），AI 会把偏差放大成"结论"：基于这份数据生成的任何"用户忠诚度洞察"都是失真的。**垃圾进、垃圾出，AI 不会替你修数据**。

### 2.3 模拟数据的结构性局限（本周最大的教训）

- 全年数据波动系数 CV=23%，87 天偏离 MA7 超 25%——在真实业务里这几乎意味着"天天异常"。异常检测阈值是人为设定，AI 不会质疑阈值本身的合理性。
- 复购率 100% 饱和，使得任何基于该指标的下钻分析（含 AI 生成）都没有区分度。**结论：AI 分析的可信度上限，被数据质量与数据分布的可靠性封顶。**

### 2.4 密钥与安全的现实约束

- API Key 硬编码是真实的高频事故源。本项目用 `.env` + `.gitignore` 双保险，并把"校验器拦截危险 SQL"作为 NL2SQL 的前置闸门——**AI 的输出永远按不可信输入处理**（最小权限原则）。

## 三、对 AI 生成内容的验证方法（本周实际执行）

| 验证手段 | 做法 | 结果 |
|---|---|---|
| SQL 白名单校验 | 表名/关键字双重校验，写操作与幻觉表名直接拒绝 | 拦截 `DROP`、`user_info` 等非法用例 ✅ |
| SQL 结果交叉验证 | NL2SQL 返回结果与第 2 周 ADS 预建表对照 | 品类 Top5 与 `ads_category_rank` 完全一致 ✅ |
| 指标口径锁定 | Prompt 固定 GMV = SUM(pay_amount_valid)，与数仓口径一致 | 生成 SQL 口径不漂移 ✅ |
| 归因结论分级 | 报告中区分"数据可证"与"待验证假设"两类结论 | 洞察报告已标注 ⚠️ |
| 人工复核 | 每条 AI 生成内容在采纳前由人工对照原始数据抽查 | 未验证的结论不进入正式文档 |

## 四、反思结论

1. **AI 是分析加速器，不是决策者**。它能写 SQL、起报告，但"哪个异常值得追"和"结论能不能用"必须由人判断。
2. **Prompt 工程的本质是数据治理的显性化**：口径不清、Schema 不明，再多 few-shot 也救不了。先治理数据，再谈智能。
3. **要为 AI 设置工程闸门**：白名单校验、只读权限、.env 密钥管理，三者缺一不可。信任要靠约束，不能靠祈祷。
4. **对模拟数据的结论保持谦抑**：本周所有洞察都应标注"基于模拟数据，方法演示性质"，答辩汇报时主动说明，不夸大 AI 能力。
