**四层链路对账**：DWD 明细、DWS 日汇总、ADS 日趋势、ADS 总览四个 GMV 均为 **25,643,462.77**，差异 0，证明聚合链路没有丢行与重复计数。

**两个新增结论**：
1. **ARPU 不能在汇总层直接相加**：`dws_user_1d.buyer_cnt` 按日相加得 14,675，真实去重用户仅 1,000（重复计数 14.7 倍），ARPU 必须回 DWD 全周期去重取数。
2. **GMV 存在双口径**：源数据 5,034 笔取消/退款/待支付订单同样写了 `pay_amount`（合计 1,282.70 万）。ADS 主口径取有效订单（2,564.35 万），全订单口径（3,847.04 万）仅作对照列，避免把没成交的钱算成业绩。

## 二·三补、口径根治 + ADS 深化分析

### 1. 口径下沉到 DWD（修掉上一轮遗留的「源头污染」）

上一轮只做到「双口径并列规避」，本轮改成从源头修：

| 改动 | 内容 |
|---|---|
| `dwd_order` 加字段 | `pay_amount_valid`、`discount_amount_valid`：加载时 `CASE WHEN is_valid_order = 1 THEN pay_amount ELSE 0 END` |
| 原始字段保留 | `pay_amount` 不动，专门留给「全订单口径对照」和「流失金额计算」 |
| DWS 改造 | 四张日汇总表全部改 `SUM(pay_amount_valid)`，删掉层层重复的 `SUM(CASE WHEN ...)` |
| 效果验证 | 四层 GMV 仍全部为 **25,643,462.77**，差异 0 —— 改造没改变任何已交付数字，只让口径不再靠人记 |

> 为什么不是直接把 `pay_amount` 置 0：那样「流失了多少钱」就永远算不出来了。留两个字段，才能做出下面的履约漏斗。

### 2. ADS 从 7 张扩到 13 张

| 新增表 | 行数 | 解决什么问题 |
|---|---:|---|
| `ads_rfm_user` | 1,000 | R/F/M 三维打分，能看出「谁快流失」，不只「谁花得多」 |
| `ads_rfm_seg_summary` | 8 | 八客群汇总：人数、GMV、人均贡献，运营可直接排优先级 |
| `ads_behavior_coverage` | 4 | 行为构成与覆盖，并显式标注 `funnel_valid = 0` |
| `ads_order_funnel` | 3 | 提交→支付→完成，逐步给出流失订单数与流失金额 |

**RFM 关键结果**：重要价值 + 重要保持 = 326 人（32.6%）贡献 **45.9%** GMV；一般挽留客户 356 人（35.6%）仍贡献 25.75% GMV，人均 1.85 万 —— 是召回主战场；重要发展客户仅 32 人但人均 3.04 万，是最容易追第二单的种子群。

**履约漏斗关键结果**：15,000 单 → 支付成功 9,966（66.44%）→ 履约完成 5,642（37.61%）。支付前流失 **1,282.70 万**（待支付 2,116 + 已取消 2,101 + 退款中 817），支付后未履约再流失 **1,113.12 万**。

### 3. 一个主动否决：行为漏斗不做

原计划做「浏览→加购→收藏→购买」转化漏斗，实测发现：

- 60,000 条行为只落在 **58,132 个会话**（人均 1.03 条），会话内根本串不起路径；
- 四类行为 UV = 1000 / 1000 / 995 / 1000，**用户覆盖率≈100%**，漏斗首步无筛选作用；
- 购买次数（11,969）**反超**加购（8,286），违反漏斗单调性。

结论：这份行为表撑不起漏斗。于是没有硬凑转化率，而是输出「行为构成与覆盖」并在表里打 `funnel_valid = 0`。答辩时这一条比多画一张图更有说服力 —— 能判断数据不可用，也是数据治理岗的能力。

## 二·四补、单品榜与门店坪效（ADS 13 张）

前 11 张表能回答「整体做得怎么样」，但经营会上最常被追问的两个问题还答不了：**到底哪几个单品在卖？门店是开得多还是开得好？**

| 新增表 | 行数 | 回答什么 |
|---|---:|---|
| `ads_product_rank` | 600 | 单品销售额排名 + 帕累托 A/B/C 分层 + 品类内排名 + 价格带 |
| `ads_store_efficiency` | 60 | 坪效 = 有效 GMV / 面积，按四分位分高效/中效/低效 |

**三个新结论**：

1. **没有爆款**：600 个 SKU 里要 **408 个**才凑出 80% 销售额，榜首单品（山地自行车）只占 0.59%，前 10 名合计 4.71%。抗风险能力强，但采购与库存极度分散。
2. **商品结构偏高价**：460 个 SKU（77%）在 2000 元以上，贡献 74.73% 销售额；100 元以下只有 8 个 SKU。
3. **门店效率严重分化（本周最反直觉的发现）**：高效组平均 174.5㎡ / 44.13 万 GMV / 坪效 2,682 元；低效组 693.9㎡ / 40.59 万 / 591.87 元。**GMV 只差 8.7%，面积差 4 倍，坪效差 4.5 倍** —— 大店没有卖出更多钱，只是占了更多地。原先「60 家门店表现均衡」的结论只在销售额维度成立。

> 这一条直接改写了 2.3 的结论，也说明「换个分母，结论会反过来」—— 坪效这个指标值得放进看板。

## 四、做得好的地方

1. **先扫描后映射**：每个枚举字段先跑 `distinct` 全量取值，再写 `case when`，没有出现分支遗漏（未命中数 = 0）。
2. **阈值可追溯**：封顶值（P95=4,745.32）与年龄均值（41）都由 SQL 动态计算并落辅助表，不是拍脑袋硬编码。
3. **修正留痕**：`is_amount_capped`、`is_amount_fixed`、`is_email_missing` 等标记字段让每笔修正都可回溯。
4. **脚本幂等**：发现外部表陷阱后全面改为 `INSERT OVERWRITE`，脚本跑 N 遍结果一致。
