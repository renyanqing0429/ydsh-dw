## 四、关键技术问题汇总（14 项）

| # | 问题 | 解决方案 |
|---|---|---|
| 1 | 浏览器下载 Docker Desktop 报 ERR_CONNECTION_RESET | 改用 curl 命令行下载 |
| 2 | 安装需管理员权限与交互 | 静默安装 `--quiet --accept-license --backend=wsl-2` |
| 3 | 引擎报 `Access is denied` / wsl.exe 被拦 | 用户从开始菜单手动启动，避免继承受限进程环境 |
| 4 | WSL 2 未安装，引擎无法启动 | `wsl --install --no-distribution` 后重启 |
| 5 | HiveServer2 起不来（Metastore 未就绪） | compose 配置 `depends_on: service_healthy` |
| 6 | 10000 端口被占用 | 排查占用进程或改端口映射 |
| 7 | CSV 导入行数不符 | 建表加 `skip.header.line.count=1` |
| 8 | docker pull 官方源超时 | DaoCloud 镜像前缀拉取 + `docker tag` 重新打标 |
| 9 | 宿主机 3306 被占用 | 容器端口改映射 3307（容器内部仍 3306） |
| 10 | Metastore `ClassNotFoundException: com.mysql.cj.jdbc.Driver` | 挂载 mysql-connector-j 到 `/opt/hive/lib` |
| 11 | Git Bash 把 `/sql/...` 改写成 Windows 路径 | `export MSYS_NO_PATHCONV=1` + `docker cp` 入容器执行 |
| 12 | 管道执行 SQL 中文注释变问号 | `docker cp` 脚本入容器，避免 Windows 管道编码转换 |
| 13 | 引擎重启后三容器 Exited(255) | `docker-compose up -d` 重新拉起 |
| 14 | hive-server 报 "Stop it first" | 陈旧 PID 文件残留，必须 `down + up` 重建，restart 无效 |

补充记录（第 15~17 项，脚本层）：`CONCAT_WS` 不接受 decimal → `CAST AS STRING`;多路 union 触发 Tez 计数器上限 → 逐表查询;`docker compose` 子命令失效 → 回退 `docker-compose`。

## 八、总结与反思

**做得好的地方**

1. 官方数据未到位时先自造等量模拟数据把流水线跑通，使后续切换官方数据只需替换文件、脚本零改动
2. 每个环境问题都即时写入《环境搭建笔记》，14 个坑都有现象、原因、解决方案，可直接复用
3. 清洗策略留有痕迹：邮箱缺失用 `is_email_missing` 打标保留而非删除，订单去重按 `order_time` 保留最新记录，符合数仓可追溯原则

**不足与改进方向**

1. 早期未拿到数据字典就推断字段，导致 4 张表建表脚本返工——后续应先确认数据源结构再动手
2. 容器数据未做卷持久化，每次 `down` 都会丢失 HDFS 数据，需靠全量重跑恢复——后续可为 HDFS 目录增加 named volume
3. 枚举脏值（约 2500 行）与斜杠日期（1902 行）本周只做了检测、未做处理，属于清洗（二）范围

**下周计划（待任务书下发）**

1. 数据清洗（二）：枚举值归一化、日期格式统一（`yyyy-MM-dd`）、手机号校验、异常金额处理
2. 维度建模：构建 DWD/DWS 层事实表与维度表（用户、商品、门店、日期）
3. 指标计算：GMV、客单价、复购率、门店销售排行等
4. 可视化：接入 Superset 搭建经营分析看板
5. 答辩准备：基于本日志与实测数据制作汇报 PPT
