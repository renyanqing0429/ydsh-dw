## 五、问题与解决

| 问题 | 现象 | 解决 |
|---|---|---|
| 月度复购率口径错位 | 第一版「分子累计/分母当月」，12 月虚高至 100% | 改为「截至当月末累计 / 累计」双累计口径，1 月 37.35% → 12 月 100.0% 单调爬升，语义正确 |
| HiveSQL 编译错误 ×2 | 外层引用子查询不存在的列；JOIN 两子查询同名列歧义 | 显式限定 `m.min_dt/max_dt`、补 `t.` 前缀消歧 |
| NL2SQL 查询 Table not found | 生成 SQL 用裸表名，默认库不是 `ydsh_dwd` | 执行器 JDBC URL 指定默认库 `jdbc:hive2://localhost:10000/ydsh_dwd` |
| 异常日检出过多 | 25% 阈值在 CV=23% 的模拟数据上命中 87 天 | Prompt 只注入偏离最深的 Top 10，报告头部声明阈值特性 |
| Git 分支基点拉错 | v2 分支从 A 分支切出，合并无冲突 | 删除重建：从 A 提交前的基点 8f22e24 切出，冲突如约触发 |
| Python 依赖环境分裂 | `pip` 与 `python` 指向不同环境，numpy 缺失 | 统一改用 `python -m pip install` 安装到当前解释器 |

## 六、反思与总结

1. **AI 应用的价值天花板由数据治理决定**。NL2SQL 能否生成正确 SQL，取决于 Schema 注入的完整性与口径是否显式化——本周把 GMV 口径写进 Prompt 后，生成 SQL 与数仓口径零漂移。先治理，再智能。
2. **对 AI 输出永远设置工程闸门**。大模型 SQL 按不可信输入处理：只读白名单 + 关键字黑名单 + 幻觉表名拦截三层防线实测有效；密钥走 `.env` 与 `.gitignore` 双保险，安全规范不是文档口号而是代码结构。
3. **人工否决案例（本周 3 处）**：① 月度复购率口径错位（AI 初版虚高 100%）；② 异常日全量清单注入（87 个导致 Prompt 失焦）；③ Git 分支基点拉错。AI 提供速度，人负责口径与逻辑把关。
4. **批判性审视贯穿始终**：复购率 100% 不当 bug 也不当成绩，如实标注为模拟数据分布特性；MAPE 13.21% 明确「可用不高精」的适用边界；同比分析因数据只有一年而如实声明不可行。不夸大、不遮掩，是本周文档写作的底线。
