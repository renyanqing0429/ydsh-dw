四、关键处理规则说明

4.1 超大金额为什么不用 P99 直接截断？

原始订单金额分布：P50 = 2,494.52、P95 = 4,832.73、P99 = 5,630,249.08、Max = 9,957,781.93。 可见 P99 已被注入的超大脏值污染，直接按 P99 设定阈值会放过真正的异常。因此采用两阶段业务规则：

  1. 异常判定：单笔支付金额 > 1 万元（约为正常 P95 的 2 倍）判为超大金额，共 312 行（占 2%）；
  2. 修正方式：不删除订单（避免丢失用户与商品维度信息），而是缩尾封顶到「正常区间（0~1 万）内的 P95 = 4,745.32」，同时打标 is_amount_capped=1，保证可追溯、可还原。

去重后实际封顶 304 行。

4.2 枚举映射为什么用「编码映射维度表」？

把 gold → 金卡会员 这类对照独立成 5 张编码映射维度表（dim_member_level_code、dim_pay_type_code、dim_order_status_code、dim_channel_code、dim_behavior_type_code），DWD 层通过 LEFT JOIN 完成转换。收益：

  • 新增一种脏取值只需 INSERT 一行映射，无需改动清洗 SQL；
  • 映射关系可被其他层复用，避免同一逻辑在多处硬编码；
  • 未命中的取值统一落到 其他，并在校验脚本中单独计数（本期未命中数 = 0）。

4.3 重复值口径

  • 原始 15,600 行中，order_id 重复组 586 个、重复多出行 600 行（其中 400 行为整行完全重复，388 组为主键相同但内容冲突）；
  • 去重后 15,000 行，主键唯一，residual_dup = 0。
